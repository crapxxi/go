# Go Task Service

Небольшой учебный проект на Go для работы с задачами обработки URL.

Проект демонстрирует:

- создание задач и управление их жизненным циклом;
- статусы задач: `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`;
- разбор URL с помощью интерфейса `URLParser`;
- хранение задач в памяти;
- обработку ошибок;
- написание unit-тестов на Go.

## Требования

- Go `1.27.1` или совместимая версия;
- Git — чтобы склонировать репозиторий.

Проверить установленную версию Go можно командой:

```bash
go version
```

## Установка и запуск

Склонируйте репозиторий и перейдите в его директорию:

```bash
git clone https://github.com/crapxxi/go.git
cd go
```

Загрузите зависимости и проверьте модуль:

```bash
go mod tidy
```

В текущей версии проекта нет отдельного `main.go`, поэтому приложение как исполняемый файл не запускается. Это библиотечный учебный проект, а основной способ проверить его работу — запустить тесты.

## Запуск тестов

Запустить все тесты:

```bash
go test ./...
```

Запустить тесты с подробным выводом:

```bash
go test -v ./...
```

Проверить код с помощью стандартного анализатора:

```bash
go vet ./...
```

Отформатировать исходный код:

```bash
gofmt -w *.go
```

## Как это работает

### 1. Создание сервиса

```go
service := NewTaskService(&DefaultURLParser{})
```

`TaskService` хранит задачи в памяти и использует переданный объект, реализующий интерфейс `URLParser`.

### 2. Создание задачи

```go
task, err := service.CreateTask(URLInput{
    RawURL: "https://example.com/api/users",
})
if err != nil {
    // Обработка некорректного URL
}

fmt.Println(task.ID)     // task-1
fmt.Println(task.Status) // PENDING
```

При создании URL проверяется. Поддерживаются только схемы `http` и `https`, а адрес должен содержать host.

### 3. Обработка задачи

```go
processedTask, err := service.ProcessTask(task.ID)
if err != nil {
    // Обработка ошибки
}

fmt.Println(processedTask.Status) // COMPLETED
fmt.Println(processedTask.Result)
```

В результате ��азбора URL доступны:

- схема — `Scheme`;
- host — `Host`;
- полный путь — `FullPath`;
- отдельные сегменты пути — `Segments`;
- количество сегментов — `SegmentCount`.

Например, для URL `https://example.com/api/users` результат будет содержать сегменты:

```text
[api users]
```

### 4. Получение задачи

```go
task, err := service.GetTask("task-1")
if err != nil {
    // Задача не найдена
}
```

Задачу со статусом `COMPLETED` или `FAILED` нельзя обработать повторно.

## Статусы задач

| Статус | Описание |
| --- | --- |
| `PENDING` | Задача создана, но ещё не обработана |
| `PROCESSING` | Задача находится в процессе обработки |
| `COMPLETED` | Обработка завершена успешно |
| `FAILED` | Во время обработки произошла ошибка |

## Возможные ошибки

Проект определяет следующие основные ошибки:

- `ErrTaskNotFound` — задача с указанным ID не найдена;
- `ErrTaskAlreadyHandled` — задача уже завершена или завершилась ошибкой;
- `ErrInvaidInput` — некорректные входные данные;
- `ErrInvalidTransition` — недопустимый переход между статусами.

> Обратите внимание: имя `ErrInvaidInput` уже используется в исходном коде с опечаткой и сохранено для совместимости.

## Ограничения текущей версии

- задачи хранятся только в памяти и исчезают после завершения программы;
- отдельного HTTP API или CLI пока нет;
- в текущем коде нет `main.go`;
- `TaskService` не предназначен для конкурентного доступа из нескольких goroutine без дополнительной синхронизации.
